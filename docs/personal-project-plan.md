# 面试练习室：个人产品实施计划

更新：2026-11-10。维护者：xbzz1018。本文是实施计划，未交付项不代表已实现。

## 1. 产品定位与可展示的个人贡献

面向准备后端与 AI 应用岗位的个人，把简历、项目代码和笔记组织成可追溯的模拟面试：先独立表达，再用证据复盘、参考和重答。首个版本只把这条流程做深，不同时扩展在线社区、套餐商城或多租户服务。

展示时讲清“解决什么问题、自己写了哪里、为什么这样设计、如何验证、还有哪些限制”。核心成果由自己的设计、代码和可复现案例支撑。

当前已经存在：资料编辑与版本冲突保护、每轮材料快照、严格/教练模式、历史恢复、逐题答法缓存、引用原话的重答比较、报告与画像分阶段、三主题。它们需要进一步评估质量，不能只用测试数量证明专业性。详见 [案例](project-case.md) 和 [来源](../NOTICE.md)。

## 2. 逐步形成自己的产品

以现有可用版为基线，按功能重做，每次交付都保留可恢复的个人数据。自己的品牌、页面、流程与维护者身份统一呈现；源码来源集中在 [NOTICE](../NOTICE.md)。

| 范围 | 决定 | 验收方式 |
| --- | --- | --- |
| 旧宣传页、Stars与赞助组件 | 已从活动源码移除 | 新入口无商业宣传或跳转 |
| 侧栏、登录、引导、欢迎页与图标 | 统一个人品牌与训练入口 | 三主题、窄屏、打包资源一致 |
| `ResumeManager.jsx`、`ResumeEditor.jsx` 及复制的编辑器 | 用自己的轻量简历流程替换 | 可迁移旧材料，PDF训练仍可用，活动代码不再依赖旧编辑器 |
| 项目材料与参考答法 | 建立自己的来源关联与引用呈现 | 问题可回到本轮代码片段与材料版本 |
| 复盘与重练 | 围绕具体缺口组织页面与下次练习 | 原话、答法、重答、练法可关联 |
| 通用模型接入、数据库、桌面基础 | 先保留稳定接口，按真实问题改进 | 已有数据和用户模型参数兼容 |
| 内部旧命名 | 仅在有迁移方案时调整 | 旧数据、IPC与配置可读，避免改名造成损坏 |

希望进一步独立实现核心模块时，从自己的用例设计和验收样本出发逐个替换；旧数据通过导出/导入转入。当前许可与第三方条款按实际保留代码记录，原作者授权范围由维护者与作者确认。

## 3. 产品结构

当前范围仅保留文字面试、材料、复盘与重答；录音复盘、实时语音辅助、音视频采集和图谱页面已移除，历史数据仍可查看。

主流程是“项目工作台 → 本轮准备 → 模拟面试 → 证据复盘 → 重答 → 下次练习”。项目工作台和证据侧栏属于待实现设计，当前界面仍从面试准备进入。

| 页面/模块 | 个人产品方向 | 暂不投入 |
| --- | --- | --- |
| 项目工作台 | 每个项目有经历事实、本人职责、代码证据与待验证项 | 泛化聊天入口、宣传统计大屏 |
| 面试准备 | 明确选项目、材料版本、岗位、严格/教练模式 | 自动全盘扫描本地磁盘 |
| 模拟面试 | 围绕本轮证据追问原理、边界、故障与验证 | 无约束出题、现场替用户编经历 |
| 复盘与重练 | 问题、原答、证据、参考框架、重答并排关联 | 只给总分、不指向原话 |
| 能力记录 | 技术和表达分别记，用户可纠正观察 | 一次模型推断永久定性 |
| 简历 | 上传与字段编辑，服务训练材料 | 多模板排版商城与复杂设计器 |

## 4. 技术取舍

保留 TypeScript、React、Hono/Bun、SQLite、Electron。新增逻辑遵守现有 core/contracts 与适配器边界，新增页面和共用代码用 TypeScript，旧 JSX 随实际修改逐步迁移，不做全仓机械翻译。

- Java：只有明确需要学习服务端部署与多用户任务时，先抽一个独立用例；不重写整套桌面端。
- Python：仅在训练、专用推理等确有需求时作为独立适配服务。
- PostgreSQL/队列：等多实例需求明确后引入，单机 SQLite 不为展示而替换。
- 模型：保留用户选择的模型、协议与推理强度。可配置不同场景，但不得静默降级；失败显式报错，质量与时延分开记录。
- Embedding：先测检索是否命中与索引是否一致，再比较模型。不要把报告等待直接归因于向量模型。

## 5. 阶段交付与完成标准

阶段顺序表示依赖关系，不是未经验证的工期承诺。每阶段独立验收后再扩展。

| 阶段 | 交付 | 完成标准 | 状态 |
| --- | --- | --- | --- |
| A 品牌与公开材料 | 新标识、图标资源、个人维护者、当前文档 | 侧栏/登录/欢迎/页签/窗口/快捷方式一致；三主题可读；来源与个人增量可查 | 已实现，源码与本机目录包通过验收 |
| B 轻量简历 | 自己实现的上传、字段/项目编辑、预览与导出备份 | 新界面不依赖复制的编辑器；现有简历可导出/恢复；PDF仍可用于面试；失败不丢旧记录 | 未实现 |
| C 项目证据 | 项目与材料/代码片段关联，引用定位与版本 | 点击答法中的引用能打开本轮快照片段；过期、缺失、无证据均有状态 | 未实现 |
| D 面试质量 | 20 场景评测与可解释追问策略 | 有固定输入、预期、真实模型结果及失败例；严格/教练和职责边界通过 | 未实现 |
| E 可恢复训练 | 重答后台任务与可见进度 | 离页/重启可查询；相同请求重放不重复成功结果；取消和旧任务覆盖有回归 | 未实现 |
| F 公开展示 | 合成演示、案例、可复现构建和发布清单 | 无私人数据；许可事项已处理；Windows新装/升级/退出/数据恢复实测；公开CI通过 | 未实现 |

A 只改变品牌，不能替代 B–E 的产品能力。源码通过独立 GitHub 仓库维护；尚未发布个人安装包。

## 6. 先替换简历编辑器

当前 `ResumeManager.jsx`、`ResumeEditor.jsx` 依赖 `frontend/src/resume/` 的存储、模板与工作台；仅隐藏路由不算移除复制实现。该模块附加条款需在公开分发前核定或替换，当前未判断已兼容。

建议新建自己的简历用例与轻量页面，不追求复刻旧设计器：基本信息、经历、项目、技能、文字预览，加 PDF 上传。字段变化和导入先进入预览，用户确认后保存新版本。

迁移要求：先导出旧浏览器数据与后端资料，定义新 schema 与转换预览；保留原数据副本，不直接改旧存储。验证缺字段、重复导入、无效 JSON、保存失败与跨账号隔离。完成替换后，检查活动 import、字体、样式与构建依赖；再确定源码分发范围。历史来源继续可追溯。

## 7. 把项目与代码证据关联起来

以下是待实现的数据设计，不是现有 API：

| 对象 | 建议字段/职责 |
| --- | --- |
| 项目卡片 | project_id、背景、本人职责、经历类型、待核对说法 |
| 证据条目 | source_id、project_id、类型、仓库相对路径、revision/commit、内容 hash、片段与行范围 |
| 说法与证据关联 | claim_id、statement、evidence_ids、确认状态；标注实际工作/团队工作/个人复现/计划 |
| 本轮快照 | 冻结选择的材料与证据内容；资料更新不回写历史 |
| 参考答法 | 考点、口述结构、证据引用、材料不足项、可选改进；建议与已做事实分开 |

导入从用户显式选择的项目目录或文件开始。只读、文件类型白名单、大小与数量上限、预览确认；默认跳过密钥文件、个人数据库、录音、构建产物和依赖目录。先做一次快照导入，再考虑增量更新，不先做全盘自动监听。

生成答法时只带相关片段与本轮快照，后端校验引用 ID 属于本轮且路径/片段确实存在。找不到证据时明确“待补充”，不能因仓库有相似实现就认定候选人做过。参数表是材料提供的配置，不自动等于训练完成；小模型个人复现与历史实习部署分别记录。

检索先测同名项目隔离、尾部事实召回、无答案、材料更新；核对 BGE pooling/归一化、查询与文档角色、token 切块及索引版本。每次模型/切块变化建立新索引标识，禁止混用不同维度或版本向量。

## 8. 固定 20 场景质量评测

| 场景组 | 数量 | 关键判定 |
| --- | --- | --- |
| 材料充分、回答正确 | 3 | 追问贴近项目，原理与证据正确，下一题不过度重复 |
| 短答、答错、明确不会 | 3 | 指出具体缺口；严格模式不提前泄题，教练模式可讲解 |
| 职责不明、团队与本人、AI协作 | 3 | 不把团队/AI工作虚报成个人独立成果，能要求澄清 |
| 缺少指标、未验证参数、复现与实习不同 | 3 | 不补造数字，不把设想说成结果，允许待补充 |
| 同名项目、错误版本、无答案 | 3 | 引用来自正确项目与本轮快照，无依据明确拒绝推测 |
| 参考后重答、仍有误区 | 2 | 技术/表达区分，缺口有原话，改进可操作 |
| 网关超时、错误结构、重试 | 3 | 状态可解释，原记录保留，无静默模型降级或重复成绩 |
| 合计 | 20 | 记录所有失败，不仅挑选成功输出 |

先用确定性测试验证协议与状态，再单独运行真实模型评测；真实调用受用户配置和费用约束。结果记录源码版本、样本版本、模型/协议/强度、首段时间、总耗时、引用正确性、事实虚构和人工评分。不得把 mock 成绩当质量成绩，也不得用两个不同对话计算提速比例。

发布门槛：固定集里无伪造本人经历/无效来源引用；发现一例即列出失败并修复。相关性、追问深度和表达帮助由人工复核，先报告基线，再决定数值目标，不预填提升百分比。

## 9. 长任务、时延与资料安全

重答比较复用现有任务基础，保存请求 ID、输入摘要、状态、attempt、结果引用和拥有者。恢复时重做未完成请求可能再次调用模型，不能承诺恰好一次；成功结果通过持久化去重，旧 attempt 不得覆盖新结果。取消、超时、进程退出和落库失败分别验证。

正文先读与画像后台继续已有基础；下一步记录每个阶段的等待，减少不相关上下文、复用成功答法与材料解析，不先牺牲用户选定的模型能力。只用匿名阶段和耗时做日志，不记录 Key、完整简历或问答正文。

个人项目材料默认只在本机保存；发送给模型前界面能确认本轮选材。代码路径/用户名在公开示例中替换为合成值。删除、导出、升级与回滚需要独立验证，不能靠忽略 Git 文件代替数据保护。

## 10. 对外展示与工作边界

项目首页：一句定位、实际训练截图、个人增量、启动验证、限制。项目案例：证据快照、引用校验、幂等重答各选一个可复现失败案例，配自己的代码和结果。历史架构明确为继承基础。

个人经历可写“维护个人面试训练项目，扩展材料快照、参考答法重练与桌面恢复，并验证失败边界”；未来交付后再补证据关联与评测结果。不要将计划列入已完成能力。

每阶段沉淀自己的设计、代码、依赖清单与测试记录，选取能够实际复现的案例展示。

下一次最小任务建议是 B 的简历迁移预览与轻量编辑，随后交付 C 的手动代码片段关联。每次带可运行改动、定向测试与一份失败案例；不同时翻新所有模块。
