# 面试练习室：公开展示与工程改进

更新：2026-11-11。区分已有能力与下一步，不把计划写成已支持功能。

## 技术选型

继续使用 TypeScript、React、Hono/Bun、SQLite 和 Electron。已有契约、用例、sidecar 和本地向量可以共同验证，不为展示而重写语言。

| 选择 | 当前决定 | 重新考虑的条件 |
| --- | --- | --- |
| Java/Spring 后端 | 暂不迁移 | 确有 Java 学习及服务端目标，先抽独立用例做对照，验证契约与数据兼容 |
| Python 模型服务 | 不替换主服务 | 训练或 Python 独有推理能力有需要时，独立适配模型端口 |
| Tauri/Rust 桌面 | 暂不迁移 | 包体/内存成为实测瓶颈，并能承担音频、权限、IPC 与打包重新验收 |
| PostgreSQL/队列 | 暂不引入 | 真实多用户、跨实例任务与监控提出需求，再改变持久化和锁语义 |

## 已有展示内容

材料编辑、revision 保护与快照；严格/教练模式、问答恢复、答法缓存和重答证据；报告/画像分阶段；Windows PDF/ONNX 交付；项目来源快照与引用、知识草稿及三主题的跨端口保存。责任范围见 [案例](project-case.md) 与 [来源](../NOTICE.md)。

阶段交付、自己的能力边界与来源关联设计见 [个人产品实施计划](personal-project-plan.md)。

## 下一步顺序

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0 | 自写轻量简历与数据迁移 | 上传、文本字段编辑与旧数据导入可用，活动代码解除对复制编辑器的依赖；第三方条款按保留范围处理 |
| P0 | 安装包发布准备 | 源码已发布；继续核对许可、平台验收与安装包校验。每次提交排除本机资料、凭据、内部笔记与构建物 |
| P1 | 固定 20 场景质量评估 | 覆盖错误/短回答、不会、AI 协作、职责不明、简历矛盾和无证据数字；记录配置、正确性、相关性及失败例 |
| P1 | 检索回归 | 核对 BGE pooling、查询/文档角色、token 安全切块、索引版本；尾部事实可召回，不混用新旧向量；记录 recall 与耗时 |
| P1 | 来源关联的下一步 | 已有明确清单、项目版本、按题检索与引用；继续补显式答法新版本、来源更新差异及真实资料召回基准 |
| P2 | 重答任务持久化 | 离页、重启有明确状态；重复请求不重复执行成功结果；测取消、断线与旧任务覆盖 |
| P2 | 等待与质量量化 | 分开记录首段/总耗时、缓存及质量；相同场景对照，不用不同单样例计算提速 |
| P2 | 个人记忆纠正 | 事实与观察可确认、修改、删除；单次模型判断不变成永久标签 |
